# 개관 체크리스트·구현 로드맵

이 문서는 개관까지의 전체 계획입니다. 현재 로컬 구현·검증과 운영 배포 여부는 [진행 현황](07-progress.md)을 기준으로 판단합니다.

## 구현 순서

순서는 위험도와 기능 의존성을 기준으로 제안했습니다. 기간 약속이 아니며 실제 배포 상태와 담당 인력이 확인되면 일정을 정합니다.

| 단계 | 작업 | 끝났다고 판단할 기준 |
| --- | --- | --- |
| 0. 기준 확보 | 서버·GitHub 차이, DB 스키마, 계정·백업 확인 | 현재 배포 버전과 복구 가능한 백업을 식별 |
| 1. P0 보완 | 관리자 권한, PIN 원문 제거, 세션 키·기본 관리자, CSRF | 학생이 관리 기능을 호출해도 읽기·변경 불가; 비밀정보 안전한 설정 |
| 2. 학생 이용 완성 | 고정 학생 ID 연결, 승인 제거, **내 예약·상세·취소**, 정보 수정 | 가입→예약→조회→취소와 정보 변경 후 이력 유지 |
| 3. 예약 안정화 | 입력·시간대·제재 검사, DB 중복 방지, 고장·휴실 | 동시 요청·잘못된 요청에도 일관된 예약 결과 |
| 4. 현장 운영 | 학생증 대조 체크인, 퇴실, 노쇼 확정·정정, 직원별 기록 | 교대 담당자가 당일 이용을 처리하고 미처리를 마감 |
| 5. 화면 개선 | 공개 홈, 브랜드·실습실 소개, 모바일 예약·내 예약 | 실제 학생·운영진이 안내 없이 핵심 흐름 수행 |
| 6. 개관 리허설 | 백업 복구·장애·고장·오입력·노쇼·교대 연습 | 치명적 문제 해결, 후임 담당자 단독 수행 |

디자인 작업은 데이터·기능 설계가 정리되는 동안 함께 준비할 수 있습니다. 기능 구현 전체를 마치기 전 실제 서비스에 승인만 먼저 없애는 순서는 피합니다. ‘내 예약’은 후속 꾸미기 작업이 아니라 학생 기능 완성 단계에 포함합니다.

## 운영진이 결정할 사항

| 항목 | 현재 근거 | 결정할 내용 |
| --- | --- | --- |
| 이용 대상 | 운영자는 외대 학생 확인을 목표로 함 | 양 캠퍼스·타 학부·대학원·휴학생·교직원 범위 |
| 본인 확인 | 매 방문 학생증 대조 | 모바일 학생증 허용 여부, 이름·학번 불일치·학번 선점 처리 |
| 실제 좌석 | 도면 27 / 주석 28 | 설치 PC 수, 학생 이용 가능 수, 예비·고장석 |
| 영업 | 화면 09–17시 | 요일·방학·시험기간, 수업·행사 우선권 |
| 예약 제한 | 기본 3시간, 하루 활성 1건 | 유지 또는 변경, 예약 가능 기간의 포함 일수 |
| 취소·변경 | 현재 학생 취소 없음 | 시작 전 취소 허용안, 지각 유예, 시작 후 예외 처리 |
| 노쇼 | 코드상 최근 1주 제한 | 확정 주체·기준·기간·이의 처리, 기존 예약 처리 |
| 현장 이용 | 직원 방문 확인 | 직원 부재 시 입실 불가 여부, 퇴실 확인 방식 |
| 문의 | 화면에 명확한 채널 없음 | 담당 부서·문의 채널·응답 시간 |
| 데이터 | 학번·이름·비밀번호·예약 이력 | 기관 담당자와 수집 목적·보관 기간·탈퇴·파기·안내 확정 |

소속 확인을 위해 학생증 사본이나 불필요한 개인정보를 추가 수집하는 흐름은 제안하지 않습니다. 안내문·개인정보 처리방침은 이 기술 문서로 대체하지 않고 학부·학교 담당자와 확정합니다.

## 시설 준비

- [ ] 좌석 번호와 실제 도면 대조, 고성능 구역·이용 가능 PC 목록 확정.
- [ ] PC·모니터·키보드·마우스·헤드셋 자산 목록, 고장 신고·수리 담당 지정.
- [ ] 설치 프로그램·게임·학교 계정의 이용 조건과 라이선스 범위를 담당자가 확인.
- [ ] 업데이트 시간, 재부팅·초기화 방식, 개인 게임·브라우저 계정 로그아웃 절차 마련.
- [ ] 네트워크·주변기기·오디오·화면 출력·전원 상태를 모든 이용 좌석에서 시험.
- [ ] 담당자용 관리 PC를 학생 공용 PC와 구분하고 세션 잠금·로그아웃 습관 마련.
- [ ] 안내 표지에 입실 절차·학생증·이용 종료·음식물·소음·장비 이상 신고 표시.
- [ ] 청소·분실물·장비 파손·응급 상황의 담당 부서 연락 절차 확인.

웹 예약 프로그램은 PC방의 요금·PC 잠금·게임 계정 관리 프로그램을 제공하지 않습니다. 이용시간이 끝나도 PC가 자동 종료되지 않으므로 초기 운영은 현장 관리 방식까지 준비해야 합니다.

## 소규모 리허설 시나리오

가상 데이터나 사전에 정한 테스트 참가자로 다음 상황을 연습합니다: 최초 가입, 동시 좌석 선택, 예약 완료 후 재로그인 조회, 취소 후 재예약, 이름 오타 정정, 학번 중복·계정 복구, 당일 학생증 불일치, 지각·노쇼·담당자 누락, PC 고장에 따른 자리 변경, 인터넷 장애, 담당자 교대, 백업 복구.

후임 담당자가 개발자에게 물어보지 않고 공지를 바꾸고 당일 방문을 처리하며 문제 발생 시 누구에게 연락할지 설명할 수 있어야 합니다. 개발 후임자는 새 PC에서 실행하고 문구 수정 PR·시험 배포·복구까지 수행해야 합니다.
