# 개발·인수인계 가이드

처음 받았다면 [여기부터 읽기](00-start-here.md)를 열고 [진행표](07-progress.md)에서 로컬 완료·배포 대기를 확인합니다. [README](../README.md)로 새 개발 환경을 실행하세요. 아래는 초기 승인형 코드가 아닌 현재 로컬 개선판 기준입니다.

## 담당별 첫 작업

| 담당 | 먼저 할 일 | 완료 확인 |
| --- | --- | --- |
| 현장 운영 | 가상 계정으로 예약·학생증 대조·체크인·종료 연습 | 다음 예약자와 좌석을 찾고 상태를 설명할 수 있음 |
| 개발 | 새 가상환경과 빈 DB에서 앱·테스트 실행 | 직접 가입·내 예약·취소·정보 수정을 재현 |
| 배포 | 실제 서버 커밋·경로·DB·백업·복구 수단 확보 | 별도 시험 환경 이관과 복구 성공 |

한 사람이 여러 역할을 맡아도 저장소·호스팅·운영 책임자를 기록합니다. 비밀번호와 복구 코드는 GitHub 문서나 ZIP에 넣지 않습니다.

## 어디를 수정하는가

| 바꾸려는 것 | 현재 위치 | 함께 확인할 것 |
| --- | --- | --- |
| 공지·예약 접수·운영시간·최대 시간·예약 기간 | 운영진 대시보드 설정 | 기존 예약은 자동 변경되지 않음 |
| 정기 수업·전체 대관·기간별 여러 좌석 차단 | 운영진 대시보드의 세 차단 메뉴 | 겹치는 날짜의 기존 예약을 먼저 안내·취소 |
| 가입·로그인·내 정보 | `templates/student_*.html`, `account.html`, `routes.py` | 비밀번호·학번 검증과 서버 권한 |
| 내 예약·상세 | `templates/my_reservations.html`, `reservation_detail.html` | 본인 예약만 조회·시작 전 또는 예약 후 5분 이내 취소 |
| 공통 메뉴·실습실명 | `templates/layout.html` | 비로그인·학생·운영진·모바일 |
| 예약 화면·좌석 선택 | `templates/index.html`, `static/js/main.js` | `booking.py`의 시간·좌석 규칙 |
| 색·여백·반응형 화면 | `static/css/style.css` | 실제 화면과 키보드 조작 |
| 로고·글꼴 | `static/images/`, `static/fonts/` | 후원사 원본·사용 권한 보존 |
| 인증·역할·시도 제한 | `auth_helpers.py`, `routes.py`, `application.py` | 우회 요청·타인 접근·세션 만료 테스트 |
| 예약 정책·시간대·중복 방지 | `booking.py`, `models.py` | 조회와 생성 규칙·동시 요청 |
| 저장 항목 | `models.py`, `migrations/` | 스키마 변경 이력·기존 데이터 보존 |
| 관리자 계정·기존 DB 이관 | `commands.py`, `legacy_import.py` | 서버 콘솔 접근·별도 새 DB·백업 |

`app.py`는 호스팅 호환 진입점이고 실제 초기화는 `application.py`의 `create_app()`입니다. 설정은 `.env` 또는 환경변수에서 읽습니다. `init_db.py`는 새 스키마 준비용이며 기존 운영 DB 변환 도구가 아닙니다.

## 수정부터 커밋까지

1. `git status`와 [진행표](07-progress.md)를 읽어 중단된 작업과 다른 사람의 변경을 확인합니다.
2. 새 작업이면 `codex/<작업명>` 브랜치를 만듭니다. 이미 진행 중인 브랜치에서는 계속 작업합니다.
3. 한 가지 목적의 코드·회귀 테스트·해당 문서를 함께 수정합니다.
4. `.\.venv\Scripts\python.exe -m pytest -q`로 관련 기능을 검증합니다. 화면 변경은 데스크톱·모바일에서도 확인합니다.
5. `git diff`, `git diff --check`, `git status`를 확인하고 의도한 파일만 stage합니다. staged diff도 읽습니다.
6. **목적이 완료되고 검증을 통과한 시점에 커밋**합니다. 문서 정리는 별도 `docs` 커밋으로 남깁니다. [상세 Git 규칙](08-git-workflow.md)을 따릅니다.
7. 진행표와 CHANGELOG에 완료·미완료·검증·배포 여부를 남깁니다. push·PR·운영 배포는 각각 별도로 기록합니다.

예를 들어 내 예약 기능 수정이라면 코드만 먼저 커밋하지 말고 소유권·취소 테스트와 사용법까지 하나의 검토 단위로 묶습니다. 문구만 바꾼 경우에는 구현을 그대로 복제하는 테스트를 추가하지 않습니다.

## 테스트와 데이터 관리

현재 `tests/`는 `create_app()`과 임시 DB·가상 학생을 사용합니다. 역할 경계, CSRF, 예약 소유권, 입력 검증, 동시 예약, 상태 전이, 정보 변경과 세션 무효화를 검증합니다. 최종 확인 범위와 결과는 [진행표](07-progress.md)에 기록합니다.

예약과 차단 시간은 DB에 자정부터의 분(`start_minute`, `end_minute`)으로 저장합니다. 예약 당시 직접 접속 주소는 `booking_ip`에 저장하며 관리자 화면에서만 확인합니다. 운영에 올릴 때에는 DB를 먼저 백업하고 같은 DB에 `flask db upgrade`를 실행해 `0003` 시간 변환과 `0004` IP 필드 추가를 완료한 뒤 웹 앱을 Reload합니다.

`tools/audit_snapshot.py`와 `test_logic.py`는 초기 구현 확인용 자료입니다. 현재 배포 전 회귀 테스트로 실행하지 않습니다. 초기 JSON을 보존해 문제의 배경을 이해하고, 새 동작은 `pytest`로 검증합니다.

모델을 바꾸면 Alembic 변경 파일을 만들고 생성된 SQL·제약·데이터 변환을 직접 검토합니다. `create_all()`은 기존 테이블 변경을 처리하지 않습니다. `0001`은 빈 DB 전용이며 기존 초기 DB에는 [별도 파일 이관](05-deployment.md)을 사용합니다. DB·실제 회원정보·환경 파일·백업·가상환경·생성 ZIP은 Git에서 제외합니다.

학번·이름을 바꿔도 예약과 제한은 변경되지 않는 내부 회원 ID에 연결합니다. 사용했던 학번은 같은 회원에게 계속 귀속하므로 다른 계정의 재가입에 사용할 수 없습니다. 학번 오입력·타인 선점 분쟁은 학생증을 대조하는 운영진 절차가 필요하며 자동 계정 복구 기능은 아직 없습니다.

인수인계용 문서 묶음은 README·CHANGELOG·`docs/`를 함께 전달합니다. 코드는 GitHub의 특정 커밋을 기준으로 받게 하고, 묶음의 생성일·기준 커밋·미배포 여부를 표기합니다. 수정 후에는 진행표와 묶음을 함께 갱신합니다.

검증·커밋 후 `.\.venv\Scripts\python.exe tools\build_handover.py --require-clean`을 실행합니다. `artifacts/`의 ZIP에는 `index.html` 시작 안내, `guide.html` 통합 가이드, Markdown 원문, 기준 커밋·파일 해시를 담은 `manifest.json`이 들어갑니다. ZIP 자체는 커밋하지 않습니다. 전달받은 사람은 압축을 푼 뒤 `index.html`부터 읽습니다.

Antigravity에서 작업한 기존 폴더와 서버 소스는 별도 보존한 뒤 GitHub와 비교합니다. 미커밋 파일·이미지 원본·WSGI 설정을 확인하고 새 clone으로 덮어쓰거나 `git reset --hard`로 지우지 않습니다.

인수인계 완료 기준은 후임자가 새 PC 실행 → 가상 학생 가입·예약·취소 → 운영진 체크인·종료 → 작은 문구 수정 PR → 시험 환경 배포·DB 복구까지 스스로 수행하는 것입니다.
