# 디자인 가이드

## 방향

실습실의 정체성과 이용 편의가 함께 드러나는 홈페이지를 목표로 합니다. 현재의 외대 네이비와 Evnia를 연상시키는 그라데이션을 출발점으로 삼되, 실제 후원사 로고·표기 규정을 확인한 뒤 브랜드 자원을 적용합니다. 아래 색·구성은 제안이며 공식 Philips Evnia 브랜드 가이드가 아닙니다.

권장안은 **밝은 예약 화면 + 네이비 브랜드 영역 + 절제된 민트·라일락 포인트**입니다. 글자와 좌석 상태는 선명하게 유지하고 공간 소개에서 사진과 브랜드 표현을 강화합니다. 다크 테마는 후속 선택지로 두어 초기 개발·운영 부담을 줄입니다.

## 필요한 페이지와 우선 정보

| 화면 | 위에서부터 보여줄 내용 | 핵심 행동 |
| --- | --- | --- |
| 공개 홈 | 실습실명·후원 소개, 오늘 운영 안내, 공간 사진, 이용 순서, 위치·문의·공지 | 예약하기 / 내 예약 |
| 가입·로그인 | 간결한 헤더, 방문 시 학생증 확인 안내, 필수 입력, 도움말 | 가입 / 로그인 |
| 예약 | 운영·예약 제한 안내, 날짜·시간, 좌석, 예약 요약 | 예약 확정 |
| 내 예약 | 가장 가까운 예약, 이용 상태, 위치·학생증 안내, 예정·지난·취소 내역 | 상세 보기 / 취소 |
| 내 정보 | 학번·이름, 정보 변경, 비밀번호 변경, 현장 복구 안내 | 변경 저장 |
| 현장 운영 | 오늘 예약 검색, 입실 대기·이용 중·종료 예정, 미처리 | 학생증 확인 후 체크인 / 퇴실 |

공개 홈 문구 초안:

> Philips Evnia Esports Lab  
> 함께 플레이하고, 배우고, 실험하는 공간.  
> 이용 시간을 예약하고, 방문 당일 학생증을 보여주세요.

학부 공식 명칭, 캠퍼스·건물·호실, 운영 시간, 문의 채널, 시설 사진은 운영진이 확인해 채웁니다. 확인되지 않은 주소·장비 성능·운영 시간은 실제 정보처럼 채워 넣지 않습니다.

## 예약과 내 예약의 연결

```text
[실습실 소개] [예약하기] [내 예약] [내 정보]

예약하기
  ① 날짜·시간 선택
  ② 좌석 선택       [가능] [선택] [예약됨] [고장/점검]
  ③ 예약 요약       날짜 / 시간 / 좌석 / 이용 안내
  [예약 확정]
        ↓
예약이 완료되었습니다
  예약 번호 / 날짜·요일 / 시간 / 좌석 / 예약 완료 상태
  방문 시 학생증을 준비해 주세요
  [내 예약 보기]
```

데스크톱에서는 좌석도와 예약 요약을 나란히 두고, 모바일에서는 날짜·시간 → 좌석 → 요약 순서로 배치합니다. 공간 도면을 유지하되 작은 화면에서는 같은 좌석 데이터의 번호 목록도 선택할 수 있게 합니다. 도면만 작게 축소해 터치 대상을 줄이지 않습니다.

내 예약의 권장 표시 예시는 ‘예약 완료 / 이용 중 / 이용 완료 / 취소 / 노쇼 확정’입니다. 날짜가 지났다는 이유만으로 학생에게 노쇼 확정 배지를 표시하지 않습니다. 예약 중지, 만석, 휴실, 로그인 만료, 조회 실패 상태마다 원인과 다음 행동을 알려줍니다.

## 스타일 기준

| 요소 | 제안 |
| --- | --- |
| 색 | 네이비 `#002C5F`, 밝은 배경 `#F4F7F9` 유지 가능. 민트·보라 포인트는 장식·브랜드 영역 위주 |
| 글꼴 | 한국어 본문을 지원하는 글꼴 우선. 브랜드용 Gladiora는 로고·영문 제목의 사용 범위를 확인 |
| 제목 | 짧고 명확한 한국어 제목. 긴 영문 실습실명은 모바일에서 로고와 줄바꿈 설계 |
| 간격 | 8px 단위의 일관된 간격과 공통 필드·버튼 높이. 인라인 스타일을 공통 CSS로 정리 |
| 좌석 | `button`으로 구현, 좌석 번호와 상태를 접근 가능한 이름에 포함 |
| 상태 | 색과 텍스트·아이콘을 함께 사용. 고성능 구분과 예약 가능 여부가 혼동되지 않게 분리 |
| 피드백 | 성공은 페이지에 남는 확인 정보, 실패는 입력 가까운 설명. alert만으로 종료하지 않기 |
| 사진·로고 | 실습실 실제 사진·기존 제공 로고 우선. 후원 관계의 표현과 로고 사용 범위를 확인 |

현재 `.seat.high-perf::after`의 별 표시에는 좌석 기준의 위치 설정이 필요합니다. 공통 요소는 헤더, 입력, 버튼, 예약 카드, 상태 배지, 좌석, 빈 상태, 오류 메시지부터 정리합니다. 관리자 차트와 Google Fonts 등 외부 자원이 실패해도 예약·방문 처리의 기본 화면은 동작하도록 합니다.

## 화면 검수 기준

- 390px 모바일과 일반 데스크톱에서 메뉴·입력·예약 버튼이 겹치지 않음.
- 모바일 첫 화면에서 화면 목적과 첫 행동이 보이며, 큰 메뉴 때문에 가입 폼이 지나치게 밀리지 않음.
- 키보드만으로 날짜·시간·좌석 선택·예약·취소 가능, 포커스 표시 유지.
- 입력에는 연결된 label을 제공하고 상태 변화는 보조기기에도 전달.
- 모든 상태에서 글자가 배경에 충분히 대비되며, 색을 구분하지 못해도 예약 상태를 이해 가능.
- 좌석 조회 중·실패 상태를 표시하고 조회 전 좌석을 확정 가능한 것처럼 보여주지 않음.
- 빠르게 시간을 바꿔도 마지막 선택에 해당하는 조회 응답만 적용.
- 공지·이용 시간·최대 예약 시간은 서버 설정을 사용하여 서로 다른 안내가 나오지 않음.
- 예약 완료 후 브라우저를 닫았다가 다시 로그인해도 ‘내 예약’에서 같은 예약을 찾을 수 있음.
