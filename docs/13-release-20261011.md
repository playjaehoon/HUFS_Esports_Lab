# PR #8 이후 달력·사진 변경 — 2026-10-11

비교 기준은 PR #8 병합 커밋 `4c0a2d0`입니다. 이번 변경은 GitHub 검토 대상이며 PythonAnywhere 운영 배포는 별도입니다.

## 변경 목적과 결과

### 달력·휴관 관리

- 관리자 일정 종류에 **일반**을 추가했습니다. 일반·행사는 안내용으로 등록하거나 예약 차단을 함께 설정할 수 있습니다. 수업·대관·휴관은 항상 해당 시간 예약을 차단합니다.
- 점검뿐 아니라 **내부 사정, 시범 운영 종료, 방학 등 자유로운 사유로 장기 휴관**을 등록할 수 있습니다. 휴관·기간 내 모든 날짜·종일을 선택하면 주말·공휴일을 포함한 기간 전체에 적용합니다. 기간은 시작일 포함 최대 366일이며 달력 공개 범위와 예약 가능 기간은 별개입니다.
- 정기 휴무·공휴일과 운영시간 전체를 막는 일정이 겹치면 **대표 휴관 제목 하나로 표시**합니다. 휴관 종류를 우선하고 별도 안내 일정은 유지합니다. 실제 예약 제한은 모든 원본 차단 일정을 기준으로 계산합니다.
- 공개 달력에서 회색으로 표시하던 일정 종류·예약 차단 설명을 없애고 **시간과 제목 중심**으로 정리했습니다.
- 관리자 목록에 **일정 삭제**를 추가했습니다. 삭제한 일정은 공개 달력·관리자 목록·예약 차단에서 제외하고 내부 기록은 보존합니다. 삭제한 일정을 다시 게시하는 복구 화면은 없습니다.
- 기존 확정 예약과 겹치는 차단 일정은 저장을 거절해 기존 예약을 보호합니다.

### 공지사항·갤러리 사진

- 여러 사진을 **한 번에 최대 10장, 게시글당 총 20장**까지 업로드할 수 있습니다. 두 제한 모두 대표 사진을 포함하며, 저장 후 편집창에서 이어서 추가할 수 있습니다.
- 사진당 업로드 한도를 **10MiB(화면 표기 10MB)**로 늘렸으며 **JPG·JPEG·PNG·WebP**를 지원합니다. 실제 파일 내용과 2천만 화소 제한을 검증합니다.
- 관리자 편집창에서 사진 표시 너비를 **본문 폭의 25~100%**로 조절하고 미리 볼 수 있습니다. 새 추가 사진에는 공통 너비를 적용하고 저장된 대표·추가 사진은 각각 수정할 수 있습니다.
- PC·모바일 모두 현재 본문 폭을 기준으로 같은 비율을 적용하고 높이는 자동으로 유지합니다. 예를 들어 50%는 모바일에서도 본문 폭의 절반입니다. 좁은 화면의 가로 넘침을 줄이도록 사진 영역을 보완했습니다.
- **추가 사진 설명은 선택 입력**입니다. 비워 두면 공개 설명 줄을 표시하지 않고 입력 시 최대 160자입니다. 대표 사진 설명은 기존처럼 필수입니다.
- 편집은 표시 너비 조절이며 자르기·회전·원본 해상도 편집 기능은 포함하지 않습니다. 외부 에디터·CDN 의존성은 없습니다.
- 공유 업로드 기능을 사용하는 팝업 사진 한도도 10MB로 맞췄습니다. 일반 요청 제한은 유지하고 관리자 게시글 업로드 요청만 101MiB, 팝업은 11MiB로 조정했습니다.

## 확인한 내용

- 최종 전체 회귀 테스트 **124개 통과**. 사진 설명 선택 입력 후속 변경까지 포함합니다.
- 실제 multipart 사진 10장×10MB 업로드, 11장 요청·21장 누적·10MB 초과 거절, JPG·PNG 혼합 업로드를 확인했습니다.
- 개별 너비 저장·공개 페이지 반영, 설명 생략, 이후 본문 수정 시 너비 보존, 잘못된 너비 거절을 검증했습니다.
- 일반·행사·대관·내부 사정 휴관·시범 운영 종료·방학 휴관 예시를 로컬에 등록하고 휴일 중복 표시와 예약 차단을 검증했습니다. 로컬에는 사진 20장 검수 게시글도 등록했습니다.
- 사진이 있는 기존 DB의 마이그레이션, 외래키·무결성 검사, JavaScript 구문 검사와 Git diff 공백 검사를 통과했습니다.
- 자동 PC·모바일 브라우저 화면 검수는 접근 제한으로 미검증입니다. CSS·공개 HTML 응답을 확인했으며 실제 화면의 최종 확인은 필요합니다.

## 배포·데이터 영향

- 최신 DB revision은 **0013**입니다. **0012**는 일반 일정과 삭제 상태를 추가하고 **0013**은 대표·추가 사진 표시 너비를 추가합니다. 실제 운영 revision을 확인한 뒤 순서대로 업그레이드합니다.
- 기존 회원·예약·게시글·일정·사진 파일과 경로를 유지합니다. 기존 사진 표시 너비는 100%, 기존 일정은 삭제되지 않은 상태로 이관합니다.
- 이미 사진이 20장을 초과한 글도 보존하며 본문·너비 수정은 가능하고 새 사진 추가만 제한합니다.
- 업로드 사진은 기존처럼 EXIF 방향 적용 후 최대 2200×2200px로 축소하고 JPEG로 변환하며 메타데이터를 제거합니다. PNG 투명 영역은 흰색으로 변환합니다. 원본 파일 그대로 보관하는 기능은 아닙니다.
- 새 패키지 의존성은 없습니다. 배포 전 **운영 DB와 사진 업로드 폴더를 함께 백업**하고 쓰기를 중지한 상태에서 마이그레이션 후 웹 앱을 Reload합니다. 운영 DB 초기화나 `create_all`로 배포하지 않습니다.
- 복구가 필요하면 배포 후 새 데이터를 별도로 보존하고 이전 코드와 대응하는 DB·사진 백업을 함께 복원합니다. 무작정 downgrade하지 않습니다. 자세한 절차는 [배포 가이드](05-deployment.md)에 있습니다.
- 로컬 검수용 일정·사진·DB·계정 정보·백업·실행 로그는 GitHub 업로드에 포함하지 않습니다.
