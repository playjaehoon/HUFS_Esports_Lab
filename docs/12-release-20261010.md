# PR #7 이후 변경 내역 — 2026-10-10

비교 기준은 PR #7 병합 커밋 `30e2e20`입니다. 이 문서는 그 이후의 이번 변경만 정리합니다. GitHub 업로드와 PythonAnywhere 운영 배포는 별도 절차이며 운영 반영은 아직 확인하지 않았습니다.

## 변경 목적과 결과

### 예약·방문·미방문 관리

- 학생은 빈 좌석에 한해 예약 시작 후 **5분까지** 예약할 수 있습니다. 예를 들어 16:00 예약은 16:05:00까지 허용하며, 16:05:01부터 거절합니다. 종료 시각은 연장되지 않고, 좌석 조회와 최종 확정에 동일한 기준을 적용합니다.
- 관리자 방문 확인은 **예약 당일 시작 10분 전부터 종료 전까지** 가능합니다. 학생증 대조 체크와 기존 이용 제한 검사는 유지합니다.
- 기존 ‘노쇼 확정’을 **미방문(No-show)**으로 변경했습니다. 예약 시작 시각부터 사유를 적어 처리할 수 있고, 이미 방문한 예약은 미방문으로 처리할 수 없습니다.
- 미방문 처리 시 즉시 **7일간 예약 정지**를 적용합니다. 더 긴 기존 제한은 단축하지 않습니다. 제한 기간과 겹치는 같은 학생의 미입실 예약도 취소하고 좌석을 해제합니다. 이미 입실한 예약이나 다른 학생의 예약에는 적용하지 않습니다. 미방문 기록과 당일 예약 제한 기록은 유지합니다.
- 실수로 비활성화한 학생은 관리자 학생 관리에서 복구할 수 있습니다. 기존 학생 식별자·예약 이력·학번 소유 기록·이용 제한을 보존합니다.

### 관리자 좌석별 예약 현황

- 날짜 조회 후 **예약 확인 목록을 먼저**, 그 아래 27석 좌석도를 표시합니다. 학생 예약 화면과 같은 좌석 배치 데이터를 사용합니다.
- 좌석도는 날짜 전체의 **예약 없음·예약 있음·차단 일정** 세 상태로 구분합니다. 날짜 전체 요약이므로 현재 시각의 빈 좌석 표시와는 다릅니다.
- 좌석을 누르면 예약 시간·학생·방문 상태·차단 사유를 간략히 확인하고 해당 예약 관리 카드로 이동할 수 있습니다. 학생 이름 검색과 관계없이 좌석도에는 그날 전체 현황을 보여줍니다.
- 수업·전체 대관·개별 좌석 점검은 같은 차단 색상으로 표시하고 상세에서 구분합니다. 방문·미방문 정보는 좌석을 눌렀을 때 확인합니다.

### 공개 달력과 운영 정책

- 메인에 **월간 실습실 일정**과 **현재 운영상태**를 추가했습니다. 운영시간·운영 요일·정기 수업·전체 대관·행사를 자동 반영하며, 개별 좌석 차단이나 학생 예약 정보는 공개 달력에 표시하지 않습니다.
- 관리자 일정 관리에서 공개 제목, 수업·대관·행사·휴관 종류, 날짜 범위, 반복 요일, 종일 또는 30분 단위 시간을 등록·수정·비활성화할 수 있습니다. 행사에는 예약 차단 여부를 별도로 설정합니다.
- 기존 전체 대관·정기 수업의 내부 사유는 공개하지 않고 일반 명칭으로 표시합니다. 별도로 등록한 공개 제목은 그대로 표시합니다.
- 기본 운영 요일은 월–금이며 관리자가 변경할 수 있습니다. **공휴일·대체공휴일에는 신규 예약이 차단**됩니다. 임시공휴일·학교 휴무는 관리자가 추가합니다.
- 공개 달력과 실제 좌석 조회·최종 예약·현장 방문 확인이 같은 운영 일정 기준을 사용합니다. 기존 예약과 겹치는 새 차단 일정은 저장을 거절합니다. 운영 요일 변경은 기존 예약을 자동 취소하지 않으므로 기존 휴일 예약을 점검하고 안내해야 합니다.
- 앞으로 공개할 달력 범위는 **0~12개월**, 기본 **3개월**입니다. 매월 자동 이동하며 관리자는 비공개 미래 일정도 미리 등록할 수 있습니다. 공개 범위 밖의 월은 직접 URL/API로 요청해도 차단합니다. 달력 공개 범위는 학생 예약 가능 기간과 별개입니다.

### 메인·모바일 디자인

- 운영상태는 **개방/휴관**만 표시합니다. 오늘 운영시간과 조회 기준 시각을 별도로 두고, 휴무 사유·행사명을 상태명에 중복해서 넣지 않습니다. 상태는 1분 간격과 화면 복귀 시 갱신합니다.
- 운영상태 영역은 구분선 대신 배경색 박스로 강조합니다. 개방은 청록색 점·글씨와 연한 청록 배경, 휴관은 회색 점과 연한 청회색 배경으로 구분합니다.
- 메인 목차 6개를 **Pretendard 700**으로 통일했습니다. 글꼴과 OFL 라이선스를 저장소에 포함해 외부 CDN 없이 제공합니다. 달력 날짜·작은 일정 글씨도 확대했습니다.
- 달력 상세의 남색 선과 회색 큰 배경을 제거했습니다. 일정별로 수업=연한 파랑, 대관=연한 청록, 행사=연한 보라, 휴관=연한 베이지 배경을 사용합니다.
- 일정은 **작은 네모 → 굵은 시간 → 일정명** 순으로 한 줄에 표시합니다. 긴 제목은 제목 칸에서 줄바꿈합니다. ‘수업 / 정기 수업’처럼 겹치는 기본 문구는 한 번만 표시합니다.
- ‘휴실’은 메인·달력·관리자 안내에서 **휴관**으로 통일했습니다. 관리자 일정 관리 바로가기도 다른 버튼과 같은 형태로 정리해 모바일 글자 잘림을 수정했습니다.

## 배포·데이터 영향

- 새 의존성 **`holidays==0.106`**을 추가했습니다. 서버에서 `pip install -r requirements.txt` 후 마이그레이션을 진행합니다.
- 최신 DB revision은 **`0011`**입니다. 공개 일정 테이블을 추가하고 운영 요일 설정이 없을 때만 기본 월–금을 넣습니다. 기존 학생·예약·게시글·팝업 데이터와 기존 설정을 보존합니다. 가상 학생·예약은 마이그레이션에 포함하지 않습니다.
- 실제 DB와 게시판 업로드 폴더를 백업하고, 서버의 현재 커밋·DB 경로·revision을 확인합니다. 쓰기를 중지한 상태에서 `flask --app app db upgrade` 후 Web Reload를 실행합니다. 운영 DB 초기화나 `create_all`로 배포하지 않습니다.
- 운영 요일·기존 주말/휴일 예약을 점검합니다. 새 운영 규칙은 예약 및 방문 확인에도 적용되므로 필요한 학생 안내를 합니다.
- 복구가 필요하면 쓰기를 중지하고 이전 코드와 대응하는 DB·업로드 백업을 함께 복원합니다. 배포 후 새로 쌓인 데이터는 별도로 보존하고 이전 백업으로 덮어쓰지 않도록 확인합니다. 무작정 downgrade하지 않습니다.
- 자세한 절차는 [배포 가이드](05-deployment.md)에 있습니다. 비밀번호·키·학생 개인정보·로컬 DB·검수 서버 파일은 이번 업로드에 포함하지 않습니다.
